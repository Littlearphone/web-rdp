# 2K 高分屏：提帧率 / 降延迟 实测报告

测量环境：**RTX 3070 + 3440×1440 @ 180Hz**（驱动 32.0.15.9174）。
编码后端探测：`primary=mediafoundation-mft, 硬件MFT=[NVIDIA H.264 Encoder MFT]`。

---

## 一、结论先说

| 指标 | 优化前 | 优化后 | 提升 |
|---|---|---|---|
| **2K 档位（maxw=2560）实测帧率** | 29.7 fps | **41.5 fps** | **+36%** |
| E2E 单帧延迟（采集→编码产出，2560×1070） | 27.9 ms（p50 23.0） | **16.5 ms（p50 16.0）** | **-41%** |
| CPU 串行段（采集回读 + 缩放 + 色彩转换） | 32.0 ms | **17.8 ms** | **-44%** |
| 中间缓冲 | 每帧多一块 10.7 MB BGRA | 无 | 省一次全量读写 |
| 采集回读 | 每帧 19.8 MB × 2 次拷贝 | 每帧 19.8 MB × 1 次 | 省 19.8 MB/帧 |

**关键结论：瓶颈不是编码，而是"每帧把 5MP 全量搬到 CPU 内存再逐像素处理"。**
NVENC 实测能力 **124.8 fps @2560×1070**，完全不是瓶颈，却被 CPU 段拖到 30–40 fps。

**关于 N 卡**：本次优化**没有使用任何 NVIDIA 专有 API**，全部是通用代码，
在 A 卡/I 卡上同样生效 —— 天然满足"无 N 卡自动回退"的要求（见第五节）。

---

## 二、瓶颈定位（优化前实测）

| 阶段 | 平均 | p50 | 说明 |
|---|---|---|---|
| ① DXGI 采集 + GPU→CPU 回读 | **11.5–16.6 ms** | 10.5 ms | 5.0 MP × 4B = **19.8 MB/帧** 经 PCIe 回读 |
| ② CPU 缩放 `DownscaleBGRA` | **12.4 ms** | 9.1 ms | 最近邻、标量逐像素 |
| ③ `BGRAToNV12` 色彩转换 | **8.1 ms** | 6.2 ms | 标量逐像素，BT.601 |
| ④ NVENC 编码 | **124.8 fps** | — | **充裕，不是瓶颈** |
| **合计** | **≈32 ms** | — | **→ 单线程上限 31 fps** |

额外发现两处**纯浪费**：
- `readbackTexture` 分配 19.8MB 并逐行拷贝 → `AcquireBGRA` **又**分配 19.8MB 再整块拷贝
  （一次采集 = 两条 19.8MB 拷贝 + 两次大块分配）
- 缩放产出中间 BGRA（10.7MB）后，色彩转换再把它整块读一遍

## 三、本次已落地的优化（全部已验证）

### 1. 融合"缩放 + 色彩转换"为一趟 (`native/colorspace.go`)
`DownscaleBGRAToNV12Into` / `DownscaleBGRAToNV12ParallelInto`：
一趟遍历直出目标尺寸 NV12，跳过中间 BGRA 缓冲。

- 实测：2560×1070 两步 12.38ms → 融合串行 **9.31ms（-25%）**，省 10.7MB/帧
- **正确性：与旧两步实现逐字节一致**（合成数据 0 差异；真实采集帧 3440×1440 也是 `0/4108800` 差异）

### 2. 按行分片并行 (`DownscaleBGRAToNV12ParallelInto`)
- 实测：串行 9.47ms → 2 线程 4.93 → 4 线程 3.91 → **6 线程 1.85ms**
- 分片按**偶数行对齐**，保证同一 UV 行不被两个 goroutine 重复写
- 并行输出与串行**逐字节一致**（2/4/8 线程均为 0 差异）
- 并发度 `OptimalNV12Workers` = min(NumCPU/2, th/2, 8)，多档位并存时避免过度抢占
- 不缩放（满分辨率）时同样走并行 —— 等尺寸下索引数学退化为恒等映射，纯色彩转换也受益

### 3. 去掉采集路径的重复全量拷贝 (`native/capture_dxgi_windows.go`)
`readbackTextureInto` / `acquireFrameInto`：回读**直接写最终缓冲**，
行距紧凑时一次整块拷贝。实测采集+回读 **11.5 → 7.6 ms**。

> **踩坑记录（重要）**：不能复用 NV12 缓冲来省分配 —— 硬件异步编码器的 `Push()` 只是
> 入队，缓冲区要等 pump goroutine 拷进 `IMFSample` 后才可复用
> （`asyncencoder.go` 明确要求"调用方必须每帧新建 NV12 切片"）。
> 复用会导致帧撕裂，因此生产路径保持每帧新建。

## 四、复现方式

```bash
cd backend
go build -o e2ebench.exe ./tools/e2ebench
# 先制造画面变化：DXGI 仅在桌面有变化时产帧，静止会测不到
./e2ebench.exe -display 0 -w 2560 -secs 10   # 2K 档位
./e2ebench.exe -display 0 -w 0    -secs 10   # 满分辨率
```

`tools/e2ebench` 会输出各阶段单帧成本、E2E 延迟、以及**融合内核 vs 旧两步的逐字节一致性对照**。

优化后实测（2560×1070，8 线程）：
```
① 采集+GPU回读      平均 10.09 ms
② 融合缩放+色彩转换   平均  7.71 ms
E2E 采集→编码产出    平均 16.54 ms (p50 16.01) → 上限 60.4 fps
正确性对照（真实采集帧 3440x1440）：不同字节 0/4108800 ✓ 逐字节一致
```

## 五、N 卡 / 自动回退 说明

| 路径 | 是否需要 N 卡 | 状态 |
|---|---|---|
| 融合并行 CPU 内核（本次落地） | **否** | ✅ 已上线，全平台一致 |
| MF 硬件编码（NVENC/QSV/AMF） | 否（已有回退） | ✅ 既有：硬件异步 MFT → 软件 MF → 纯 Go JPEG |
| NvFBC（NVENC 专用采集） | 是 | ❌ 消费级 GeForce 默认不启用，需 GRID/vGPU 授权 |
| NVENC SDK 直连 | 是 | ⚠️ 仅省 sample/buffer 创建开销，**对当前"回读+CPU 转换"瓶颈无帮助** |
| D3D11 VideoProcessor（GPU 缩放） | **否**（通用） | ⚠️ 本机未验证通过，见第六节 |

**"无 N 卡自动回退"已经天然满足**：本次改动是纯 CPU 通用代码，
加上既有的三级编码回退链，整个路径不依赖任何厂商专有 API。

## 六、GPU 缩放（方案 A）与遗留问题

理论上最彻底的方案：在 GPU 上把桌面纹理缩到目标尺寸，只回读缩小后的数据。
既可省掉 CPU 缩放，又能把回读量从 19.8MB 降到 ~11MB。

**本机实测未能打通**：
- `ID3D11VideoDevice` QI **成功**（hr=0x0）
- `ID3D11VideoContext` QI **成功**（hr=0x0）
- `CreateVideoProcessorEnumerator` 在 **2 个适配器 × 3 种 usage × 3 组尺寸**下
  一律返回 **E_INVALIDARG (0x80070057)**
- 已排除：desc 布局（结构体实测 36 字节，与 SDK 一致）、
  缺少 `D3D11_CREATE_DEVICE_VIDEO_SUPPORT`（加标志 0x820 后结果不变）、
  usage 取值、分辨率不受支持

→ **不宣称 GPU 缩放可用**。落地前需把该调用的参数/约束查清，
且必须保留 CPU 回退（本节的结论也说明：即便打通，收益也只是"省掉剩余的 CPU 转换"，
因为回读本身 10ms 仍在）。

**其他待办（按收益排序）**：
1. **脏矩形（dirty rects）**：DXGI 已给出脏矩形，静态桌面下只转换变化区域，
   收益与画面变化面积成正比（远程办公场景通常变化 <10%）。
   前置条件：需改造编码器缓冲所有权（新增 `PushCopy` 或归还信号），
   否则"只更新局部 + 复用缓冲"与每帧新建的要求冲突。
2. **编码输入零拷贝**：复用 `IMFSample`/`IMFMediaBuffer`，或让 MFT 直吃 D3D 纹理
   （`attachD3D` 已设 D3D manager，但输入仍走系统内存 sample，D3D 通路没被用起来）。
3. 浏览器端渲染/解码环节未纳入本次测量（本次测的是服务端管线）。

## 七、未验证 / 边界

- 多显示器与混合 DPI 场景未测
- 满分辨率（3440×1440）档位实测帧率约 38–41 fps，与优化前基本持平
  （该档位瓶颈已转移到 PCIe 回读，CPU 转换并非主导）——进一步提升需第六节的脏矩形或 GPU 缩放
- 静止桌面 8s 无帧属正常（DXGI 只在有变化时产帧），未纳入延迟统计
